The 4-Week LLD Sprint

From basic OOP pillars to complex FAANG-level machine coding rounds.

Week 1

Core OOP & SOLID Principles

Before drawing diagrams or writing patterns, your foundational code must be pristine. Interviews are lost here by writing procedural code in an OOP language.

📚 Topics to Master

  • The 4 Pillars: Encapsulation, Abstraction, Inheritance, Polymorphism. Understand when to favor Composition over Inheritance.
  • SOLID Principles: SRP, OCP, LSP, ISP, DIP. You must be able to spot violations of these in badly written code.
  • UML Basics: Class diagrams, Use Case diagrams. Know how to represent aggregation vs composition (hollow vs solid diamond).
  • Clean Code: Meaningful naming, function purity, avoiding deep nesting, handling exceptions gracefully.

⚔️ The Crucible (Practice)

  • Design a Parking Lot — The classic entry-level LLD question. Focus on finding the right actors and entities.
  • Design an Elevator System — Focuses on state and scheduling algorithms.
Mindset Shift: Stop thinking about "functions that manipulate data" and start thinking about "objects that collaborate via messages."
Head First OOA&D Clean Code (Uncle Bob)
Week 2

Creational & Structural Patterns

Patterns are standard vocabulary for solving common design problems. Using them shows maturity, forcing them shows inflexibility.

📚 Topics to Master

  • Creational: Singleton, Factory Method, Abstract Factory, Builder. Know how to construct complex objects safely.
  • Structural: Adapter, Decorator, Facade, Proxy. Know how to wrap, combine, and protect existing objects.
  • Inversion of Control (IoC): Dependency Injection containers. How does Spring or NestJS wire up your classes?

⚔️ The Crucible (Practice)

  • Design a Vending Machine — Use the State pattern (wait, that's behavioral, but good to introduce) and Factory for item dispensing.
  • Design a Library Management System — Heavy focus on class structure, enums, and inheritance hierarchies.
Mindset Shift: Don't use a pattern unless the specific pain point it solves is present. The simplest code that works beats a needlessly complex Builder pattern.
Head First Design Patterns Refactoring.guru
Week 3

Behavioral Patterns & State

This is where most machine coding rounds are won or lost. Behavioral patterns dictate how objects talk to each other without getting tightly coupled.

📚 Topics to Master

  • Behavioral: Strategy, Observer, Command, State, Chain of Responsibility.
  • State Machines: How to model complex workflows (e.g., Order → Paid → Shipped → Delivered) using the State pattern instead of massive if/else blocks.
  • Event-Driven OOP: Using the Observer pattern (Pub/Sub) to decouple core domain logic from side-effects (like sending emails).

⚔️ The Crucible (Practice)

  • Design an Amazon Online Shopping System — Focus on the Order state machine, Shopping Cart pricing (Strategy for discounts), and Notification system (Observer).
  • Design a Tic-Tac-Toe / Chess Game — Focus on rules validation (Chain of Responsibility) and game state (Command for undo/redo).
Mindset Shift: If you find yourself passing boolean flags deep into functions, or writing giant switch statements based on status codes, you need a behavioral pattern.
Clean Architecture
Week 4

Concurrency & Mock Interviews

The final boss. Handling multiple threads accessing your objects simultaneously, and doing it all under extreme time pressure (45-60 mins).

📚 Topics to Master

  • Concurrency Basics: Locks, Mutexes, Semaphores, Thread Pools, Deadlocks.
  • Thread-Safe Patterns: Thread-safe Singleton (Double-checked locking), Concurrent HashMaps, Immutable objects.
  • Optimistic vs Pessimistic Locking: When modeling databases in memory, how do you handle two users booking the same seat?

⚔️ The Crucible (Practice - 45 Min Timeboxed)

  • Design a Movie Ticket Booking System (BookMyShow) — Core challenge: Concurrency. Two users trying to book the same seat at the exact same millisecond.
  • Design an In-Memory Cache (LRU/LFU) — With O(1) operations, generic types, and thread safety.
Mindset Shift: An incomplete but working, well-designed, thread-safe core is always better than a feature-complete system with spaghetti code and race conditions.

Design Patterns Cheatsheet

The 14 most critical patterns for Machine Coding rounds.

Creational (Object Instantiation)
Singleton C
Need exactly one instance of a class across the app.
When: Config managers, Connection Pools, Caches.
Must be thread-safe (Double-checked locking).
Factory Method C
Delegate instantiation logic to subclasses.
When: Payment gateway router (CreditCard vs UPI).
Returns an Interface, hides concrete class.
Abstract Factory C
Families of related objects.
When: Cross-platform UI elements (MacButton vs WinButton).
Builder C
Constructor has 10+ optional parameters.
When: Building complex queries or configuration objects.
Using fluid interfaces: `.withName("x").build()`
Structural (Class Composition)
Adapter S
Incompatible interfaces need to work together.
When: Integrating 3rd-party Stripe API to your internal Payment interface.
Decorator S
Add behavior dynamically without inheritance subclass explosion.
When: Base Pizza class → add Cheese Decorator → add Pepperoni Decorator.
Facade S
Complex subsystem needs a simple entry point.
When: `OrderFacade.placeOrder()` hides Inventory, Payment, and Shipping subsystems.
Proxy S
Control access to an object.
When: Caching proxy (check cache before hitting DB), or Protection proxy (Auth check).
Behavioral (Object Communication)
Strategy B
Multiple algorithms for the same task, switchable at runtime.
When: Sorting algorithms, Pricing plans (Standard vs Prime vs HolidayDiscount).
Observer B
1-to-many dependency; notify others when state changes.
When: Event bus, notifying users when an Out-of-stock item is back.
State B
Object behavior changes completely based on its internal state.
When: Vending Machine (Idle, HasMoney, Dispensing), Order (Placed, Shipped).
Command B
Encapsulate a request as an object (Action → Object).
When: Undo/Redo functionality in a Text Editor or Game.
Chain of Resp. B
Pass request along a chain of handlers.
When: Authentication → Logging → Validation → Formatting middleware string.
Iterator B
Traverse elements without exposing underlying representation.
When: Iterating over a custom Graph or Tree structure in BFS/DFS order.

The 45-Minute Machine Coding Framework

How to approach a FAANG LLD interview from zero to working code.

1
Requirements & Scope 0-5 mins
Clarify exactly what features are in scope and out of scope. E.g., for a Vending Machine: "Do we handle card payments or just cash?" "Do we need an admin interface to refill items?" Record these as bullet points.
2
Core Entities & Relations 5-10 mins
Identify the nouns. E.g., for a Parking Lot: ParkingLot, Level, ParkingSpot, Vehicle, Ticket. Define relations: "A Level has multiple Spots." Don't write methods yet, just class signatures and member variables.
3
Identify Interfaces & Patterns 10-15 mins
Where will the system change? If Pricing can change, create a PricingStrategy interface. If Vehicle types can change, make Vehicle abstract. This shows your L4/L5 seniority.
4
Implement Core Logic 15-35 mins
Flesh out the most complex API first. E.g., parkVehicle(). Make sure it's thread-safe if required. Write clean code: no magic numbers, proper exception handling, meaningful variable names.
5
Driver Code & Edge Cases 35-45 mins
Write a main() method that proves your design works. Test edge cases: What if the lot is full? What if an invalid ticket is presented? Discuss scalability bottlenecks if the app were distributed.

Evaluation Rubric: L3 vs L4 Expectations

Skill Area Junior (SDE 1 / L3) Mid-Level (SDE 2 / L4)
Code Quality Methods might be long. Naming is okay. Solves the immediate problem. Pristine naming. Short, single-purpose methods. Strict adherence to SOLID.
Design Patterns Might use simple inheritance. Hardcodes behaviors (e.g., if/else for Pricing). Uses Interfaces gracefully. Injects dependencies. Anticipates future extension (Strategy/State).
Concurrency Rarely asked or expected to write thread-safe code. Actively identifies race conditions. Uses Concurrent collections or ReentrantLocks appropriately.
Testing Tests happy paths in a main method. Highlights edge cases, explains how code is mocked/tested via DI.
