🛠️ Creational Patterns

These design patterns provide various object creation mechanisms, which increase flexibility and reuse of existing code.

1. Factory Method

🎯 Interview Cheat Sheet

  • The Core Concept: Provides an interface to abstract away object instantiation (the new keyword), letting subclasses decide what concrete classes to create based on dynamic conditions or configurations.
  • Mental Model: Think of a Logistics App or an Asteroid Game. Instead of complex if/else logic scattered everywhere to spawn a Ship vs. Truck (or a Fast vs. Slow Asteroid), you delegate the creation logic to dedicated Factory subclasses.
  • FAANG Applications:
    • "Design a Notification System" (Amazon/Uber): Decouples the main logic from the specifics of creating Email, SMS, or Push notification objects.
    • "Design a Document Reader" (Google): The factory determines the appropriate parser when opening PDF, Word, or TXT files.
    • "Design an In-Memory File System" (Meta): Spawning Directory or File nodes dynamically based on user input without exposing instantiation logic.

☕ Java Implementation

interface Button { 
    void render(); 
}

class WindowsButton implements Button { 
    public void render() { 
        System.out.println("Windows Button"); 
    } 
}

// Creator Class
abstract class Dialog {
    // The Factory Method
    abstract Button createButton();
    
    public void renderWindow() {
        Button okButton = createButton();
        okButton.render();
    }
}

// Concrete Creator
class WindowsDialog extends Dialog {
    @Override
    Button createButton() { 
        return new WindowsButton(); 
    }
}

2. Abstract Factory

🎯 Interview Cheat Sheet

  • The Core Concept: A "factory of factories". It lets you produce families of related or dependent objects without specifying their concrete classes.
  • Mental Model: Think of UI Themes (Light vs. Dark Mode) or a Furniture Shop (Modern vs. Victorian). You don't want to accidentally mix a Victorian Chair with a Modern Sofa. An Abstract Factory guarantees you get objects that match the current family/theme.
  • FAANG Applications:
    • "Design a Payment Gateway System" (Stripe/PayPal): Ensuring compatibility. E.g. Stripe requires StripeRequest and StripeValidator, while PayPal requires PayPalRequest and PayPalValidator.
    • "Design a Cross-Platform UI Framework" (Meta): Rendering native UI elements (Buttons, Checkboxes) across Mac, Windows, and Linux simultaneously without mixing them.
    • "Design a Cloud Infrastructure Provisioner" (AWS/Google): Generating sets of related resources (VM, Storage, Network) specific to AWS vs. GCP using a single codebase.

☕ Java Implementation

interface GUIFactory {
    Button createButton();
    Checkbox createCheckbox();
}

class WinFactory implements GUIFactory {
    public Button createButton() { return new WinButton(); }
    public Checkbox createCheckbox() { return new WinCheckbox(); }
}

class Application {
    private Button button;
    
    // The app doesn't know the exact concrete classes
    public Application(GUIFactory factory) {
        button = factory.createButton();
    }
    
    public void paint() { 
        button.paint(); 
    }
}

3. Builder

🎯 Interview Cheat Sheet

  • The Core Concept: Extracts object construction into separate Builder objects, allowing you to construct complex objects step by step and avoid massive "telescoping" constructors.
  • Mental Model: Think of Building a House. It's built step-by-step (walls, roof, pool, garage). A Director class can even control the sequence of the builder's steps.
  • FAANG Applications:
    • "Design an SDK or API Client" (Amazon/Google): Building complex HTTP requests with optional headers, auth tokens, and payloads. It prevents bloated "telescoping" constructors.
    • "Design a Query Builder / ORM" (Meta): Constructing complex SQL queries (SELECT, WHERE, JOIN) step-by-step before calling .execute().
    • "Design a Document Converter" (Microsoft): Parsing an RTF document and step-by-step building an HTML or PDF representation using different builders under a single director.

☕ Java Implementation

class Car {
    private String engine;
    private int seats;
    
    // Private constructor prevents direct instantiation
    private Car(Builder builder) {
        this.engine = builder.engine;
        this.seats = builder.seats;
    }
    
    public static class Builder {
        private String engine;
        private int seats;
        
        public Builder setEngine(String engine) {
            this.engine = engine;
            return this;
        }
        public Builder setSeats(int seats) {
            this.seats = seats;
            return this;
        }
        public Car build() {
            return new Car(this);
        }
    }
}
// Usage: Car c = new Car.Builder().setSeats(4).build();

4. Prototype

🎯 Interview Cheat Sheet

  • The Core Concept: Lets you copy existing objects without making your code dependent on their classes. Usually implemented via a clone() method.
  • Mental Model: Think of Mitotic Cell Division or copying a template document. The original object acts as the prototype and takes an active role in creating its own identical copy.
  • FAANG Applications:
    • "Design a Game Engine" (Uber/Meta): Instead of costly DB hits or parsing JSON to recreate heavy objects (like NPCs), keep pre-initialized prototypes in a registry and just clone() them when needed.
    • "Design a Collaborative Document Editor" (Google Docs): When a user duplicates a massive slide or document page, a deep clone is much faster than re-instantiating all child elements.
    • "Design a Configuration Registry" (AWS): Bootstrapping new microservices with identical base configurations by cloning a master template config.

☕ Java Implementation

abstract class Shape implements Cloneable {
    public int x, y;
    
    public Shape() {}
    
    // Copy constructor
    public Shape(Shape target) {
        if (target != null) {
            this.x = target.x;
            this.y = target.y;
        }
    }
    
    public abstract Shape clone();
}

class Circle extends Shape {
    public int radius;
    
    public Circle(Circle target) {
        super(target);
        if (target != null) { 
            this.radius = target.radius; 
        }
    }
    
    @Override
    public Shape clone() { 
        return new Circle(this); 
    }
}

5. Singleton

🎯 Interview Cheat Sheet

  • The Core Concept: Ensures a class has only one instance and provides a global access point. It relies on a private constructor and a public static getInstance() method.
  • Mental Model: Think of The Government. A country has only one official government globally accessible by title.
  • FAANG Applications:
    • "Design a Logger or DB Connection Pool" (General FAANG): You must ensure only one instance coordinates writes to a file or manages limited DB connections. Knowing how to implement Double-Checked Locking is critical.
    • "Design an In-Memory Cache" (Amazon): A single, globally accessible cache store that multiple threads read/write to.
    • "Design a Rate Limiter" (Stripe/Uber): A centralized component tracking IP requests across the entire application lifecycle.
  • ⚠️ Red Flag / Anti-Pattern: In modern design, Singleton is often considered a code smell. It introduces untestable global state and incorrectly assumes you will never need a second instance (e.g., a single Chat Room that later needs to scale to multiple rooms).

☕ Java Implementation

public class Database {
    // volatile ensures changes to instance are 
    // immediately visible to all threads
    private static volatile Database instance;
    
    // Private constructor
    private Database() {}
    
    // Double-checked locking
    public static Database getInstance() {
        if (instance == null) {
            synchronized (Database.class) {
                if (instance == null) {
                    instance = new Database();
                }
            }
        }
        return instance;
    }
}

🧱 Structural Patterns

These patterns explain how to assemble objects and classes into larger structures while keeping these structures flexible and efficient.

1. Adapter

🎯 Interview Cheat Sheet

  • The Core Concept: Allows objects with incompatible interfaces to collaborate by wrapping one object to adapt its interface to the other.
  • Mental Model: Think of a Power Plug Adapter or a USB-to-SD Card Reader. You have an SD card, but your laptop only accepts USB. The adapter translates between the two interfaces.
  • FAANG Applications:
    • "Design a Payment Gateway Integrator" (Stripe/PayPal): Unifying a messy legacy XML payment API and a modern REST JSON API under one common internal interface.
    • "Design a Third-Party Auth Wrapper" (Google): Adapting various OAuth providers (Facebook, Twitter) to a standardized UserAuth interface.
  • 📺 Video Insight (ep 8): Instead of changing existing code (which violates the Open-Closed Principle), the Adapter implements the Target interface and wraps the Adaptee. E.g. Making a Turkey act like a Duck.

☕ Java Implementation

// Target interface
interface UsbPort { void plugInUsb(); }

// Adaptee (Incompatible interface)
class SdCard {
    public void insertIntoSlot() { System.out.println("SD Card inserted."); }
}

// Adapter
class SdCardAdapter implements UsbPort {
    private SdCard sdCard;
    
    public SdCardAdapter(SdCard sdCard) {
        this.sdCard = sdCard;
    }
    
    @Override
    public void plugInUsb() {
        sdCard.insertIntoSlot();
    }
}

2. Bridge

🎯 Interview Cheat Sheet

  • The Core Concept: Splits a large class into two separate hierarchies—Abstraction and Implementation—which can be developed independently. Prefer composition over inheritance.
  • Mental Model: Think of Universal Remote Controls. You have a Remote (Abstraction) and a TV (Implementation). Instead of creating SonyAdvancedRemote and SamsungBasicRemote, you compose a generic Remote with a Device interface.
  • FAANG Applications:
    • "Design a Cross-Platform GUI Toolkit" (Apple): Separating logical UI components (Button, Window) from OS-specific rendering APIs (WindowsRenderer, MacRenderer).
    • "Design a Messaging App" (Meta): Separating the logical message (EncryptedMessage) from the transmission protocol (SMS, WebSockets).
  • 📺 Video Insight (ep 11): Prevents the "Cartesian Product" class explosion problem where adding one dimension of variation requires multiplying all existing subclasses.

☕ Java Implementation

// Implementation
interface Device {
    void turnOn();
    void turnOff();
}

// Abstraction
abstract class RemoteControl {
    protected Device device;
    
    public RemoteControl(Device device) { this.device = device; }
    public abstract void togglePower();
}

// Refined Abstraction
class AdvancedRemote extends RemoteControl {
    public AdvancedRemote(Device device) { super(device); }
    
    @Override
    public void togglePower() {
        // delegates to device
        device.turnOn(); 
    }
}

3. Composite

🎯 Interview Cheat Sheet

  • The Core Concept: Lets you compose objects into tree structures and work with them as if they were individual objects.
  • Mental Model: Think of an OS File System or a Delivery Box. A folder contains files or other folders. A box contains items or smaller boxes. You call getSize() on the root folder, and it recursively calculates everything.
  • FAANG Applications:
    • "Design a File System" (Microsoft): Directory and File both implement FileSystemNode.
    • "Design a UI Component Tree" (Meta/React): Elements and Containers. Calling .render() on the root DOM node cascades down.
  • 📺 Video Insight (ep 14): Treats individual objects (Leaves) and compositions (Nodes) uniformly. Often used for Menus containing Sub-Menus and MenuItems.

☕ Java Implementation

interface FileSystemNode {
    int getSize();
}

class File implements FileSystemNode {
    private int size;
    public File(int size) { this.size = size; }
    public int getSize() { return size; }
}

class Directory implements FileSystemNode {
    private List children = new ArrayList<>();
    
    public void add(FileSystemNode node) { children.add(node); }
    
    public int getSize() {
        return children.stream().mapToInt(FileSystemNode::getSize).sum();
    }
}

4. Decorator

🎯 Interview Cheat Sheet

  • The Core Concept: Lets you dynamically attach new behaviors to objects by placing them inside special wrapper objects that contain the behaviors.
  • Mental Model: Think of Wearing Clothes. You are a base object. You put on a sweater (Decorator 1) and a raincoat (Decorator 2). You still implement the "Human" interface, but your behavior (warmth, waterproof) dynamically stacks.
  • FAANG Applications:
    • "Design a Coffee Point-of-Sale" (UberEats): Stacking condiments (Milk, Mocha) onto a base Beverage without subclass explosions.
    • "Design a Network Data Stream" (Java I/O): Wrapping a file stream with GZIPOutputStream then BufferedOutputStream.
  • 📺 Video Insight (ep 3): A primary application of the "Open-Closed Principle". It wraps the object to add functionality at runtime rather than relying on static compile-time inheritance.

☕ Java Implementation

interface Coffee { double getCost(); }

class SimpleCoffee implements Coffee {
    public double getCost() { return 2.0; }
}

abstract class CoffeeDecorator implements Coffee {
    protected Coffee decoratedCoffee;
    public CoffeeDecorator(Coffee coffee) { this.decoratedCoffee = coffee; }
}

class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) { super(coffee); }
    
    public double getCost() {
        return super.decoratedCoffee.getCost() + 0.5;
    }
}

5. Facade

🎯 Interview Cheat Sheet

  • The Core Concept: Provides a simplified, higher-level interface to a complex subsystem of classes, libraries, or frameworks.
  • Mental Model: Think of a Smart Home Hub. Instead of manually controlling the TV, lights, and AC separately, you tell the Hub "Movie Mode" and it orchestrates the complex subsystems behind the scenes.
  • FAANG Applications:
    • "Design a Video Conversion Library" (Netflix): Hiding codec extraction, bitrates, and audio mixing behind a simple convert("file.mp4").
    • "Design an Order Processing System" (Amazon): Hiding Inventory, Payment, and Shipping APIs behind a single checkout() method.
  • 📺 Video Insight (ep 9): Directly implements the "Principle of Least Knowledge" (Law of Demeter). It decouples the client code from the inner workings of a complex subsystem.

☕ Java Implementation

// Complex subsystem parts
class InventorySystem { void check() {} }
class PaymentSystem { void process() {} }
class ShippingSystem { void ship() {} }

// Facade
class OrderFacade {
    private InventorySystem inventory = new InventorySystem();
    private PaymentSystem payment = new PaymentSystem();
    private ShippingSystem shipping = new ShippingSystem();
    
    public void placeOrder() {
        inventory.check();
        payment.process();
        shipping.ship();
    }
}

6. Flyweight

🎯 Interview Cheat Sheet

  • The Core Concept: Fits more objects into RAM by sharing common parts of state between multiple objects (intrinsic state) instead of keeping all data in each object.
  • Mental Model: Think of a Forest in a Video Game. Instead of 1,000,000 tree objects each storing a heavy 3D mesh, store the mesh in one TreeModel (intrinsic) and let the lightweight Tree objects (extrinsic: X, Y coords) reference it.
  • FAANG Applications:
    • "Design a Game Engine" (Epic/Meta): Rendering thousands of particles, bullets, or NPCs by sharing the base models and textures.
    • "Design a Text Editor" (Google Docs): Storing font and formatting data for millions of characters efficiently to prevent browser crashes.

☕ Java Implementation

// Intrinsic State (Heavy, Shared)
class TreeType {
    private String name;
    private String color;
    private String otherTreeData;
    // constructor & methods
}

// Factory to manage shared pool
class TreeFactory {
    static Map treeTypes = new HashMap<>();
    public static TreeType getTreeType(String name) {
        return treeTypes.computeIfAbsent(name, n -> new TreeType(n));
    }
}

// Extrinsic State (Lightweight, Unique)
class Tree {
    private int x, y;
    private TreeType type; // Reference to shared state
    
    public Tree(int x, int y, TreeType type) {
        this.x = x; this.y = y; this.type = type;
    }
}

7. Proxy

🎯 Interview Cheat Sheet

  • The Core Concept: Provides a substitute or placeholder for another object to control access to it, allowing you to intercept requests before or after they reach the original object.
  • Mental Model: Think of a Credit Card or a Club Bouncer. A credit card is a proxy for a bank account (lazy loading of cash). A bouncer checks ID before letting you access the club (access control).
  • FAANG Applications:
    • "Design a Rate Limiter / API Gateway" (Stripe/Netflix): A Protection Proxy that blocks unauthorized or excessive requests before hitting the actual service.
    • "Design an Image Viewer with Infinite Scroll" (Pinterest): A Virtual Proxy that shows a placeholder and only loads the high-res image when it scrolls into view (Lazy Initialization).
    • "Design a Distributed Cache" (Redis): A Remote Proxy that handles network communication transparently.

☕ Java Implementation

interface VideoDownloader { void downloadVideo(String url); }

class RealDownloader implements VideoDownloader {
    public void downloadVideo(String url) {
        System.out.println("Downloading from network...");
    }
}

class CachedDownloaderProxy implements VideoDownloader {
    private RealDownloader downloader = new RealDownloader();
    private Map cache = new HashMap<>();
    
    public void downloadVideo(String url) {
        if (!cache.containsKey(url)) {
            downloader.downloadVideo(url);
            cache.put(url, "Downloaded Data");
        } else {
            System.out.println("Returning from cache...");
        }
    }
}

⚔️ Pattern Comparisons: Composite vs Decorator

📺 Video Insight (ep 15)

  • The Confusion: Both patterns rely on recursive composition and implementing a shared interface. They look identical structurally in code.
  • The Difference (Intent):
    • Composite: Focuses on aggregating objects into a part-whole hierarchy (a tree). The composite object itself adds no new behavior; it simply delegates the call to its children (e.g. summing up file sizes).
    • Decorator: Focuses on dynamically adding new behavior or responsibilities to a single wrapped object at runtime (e.g. adding tax to a price).
  • Mental Check: Ask yourself: "Am I managing a collection of items (Composite), or am I extending the behavior of one specific item (Decorator)?"

🧠 Behavioral Patterns

These patterns are concerned with algorithms and the assignment of responsibilities between objects.

1. Chain of Responsibility

🎯 Interview Cheat Sheet

  • The Core Concept: Passes a request along a chain of handlers. Upon receiving a request, each handler decides either to process it or to pass it to the next handler.
  • Mental Model: Think of Tech Support Escalation. Level 1 support tries to fix your issue. If they can't, they pass you to Level 2, and so on until someone resolves it.
  • FAANG Applications:
    • "Design an API Gateway/Middleware" (Stripe/Netflix): Processing incoming HTTP requests through Authentication, Rate Limiting, Logging, and Routing handlers in sequence.
    • "Design an Event Bubbling System" (Meta/React): A UI click event travels up the DOM tree until a component with an `onClick` listener catches and handles it.

☕ Java Implementation

abstract class Handler {
    protected Handler next;
    public void setNext(Handler next) { this.next = next; }
    public abstract void handleRequest(String request);
}

class AuthHandler extends Handler {
    public void handleRequest(String request) {
        if (request.equals("AuthFailed")) {
            System.out.println("Blocked by Auth.");
        } else if (next != null) {
            next.handleRequest(request);
        }
    }
}

class LogHandler extends Handler {
    public void handleRequest(String request) {
        System.out.println("Logging: " + request);
        if (next != null) next.handleRequest(request);
    }
}

2. Command

🎯 Interview Cheat Sheet

  • The Core Concept: Turns a request into a stand-alone object that contains all information about the request, allowing parameterization of methods, delayed execution, and queueing.
  • Mental Model: Think of a Restaurant Order. You give your order (Command) to the waiter (Invoker). The order is written on paper, queued in the kitchen, and eventually executed by the chef (Receiver).
  • FAANG Applications:
    • "Design a Text Editor with Undo/Redo" (Google Docs): Every action (Type, Delete, Bold) is a Command object pushed to a stack. Calling `.undo()` reverses the state.
    • "Design a Task Scheduler" (AWS/Azure): Wrapping background jobs into serialized Command objects that can be placed in an SQS queue and executed by worker nodes.

☕ Java Implementation

interface Command { void execute(); void undo(); }

class Light { 
    void turnOn() {} 
    void turnOff() {} 
}

class LightOnCommand implements Command {
    private Light light;
    public LightOnCommand(Light light) { this.light = light; }
    
    public void execute() { light.turnOn(); }
    public void undo() { light.turnOff(); }
}

class RemoteControl { // Invoker
    private Command command;
    public void setCommand(Command command) { this.command = command; }
    public void pressButton() { command.execute(); }
}

3. Iterator

🎯 Interview Cheat Sheet

  • The Core Concept: Lets you traverse elements of a collection without exposing its underlying representation (list, stack, tree, etc.).
  • Mental Model: Think of an MP3 Player Playlist. You just press "Next" to get the next song, regardless of whether the playlist is stored as an array, linked list, or pulled dynamically from the cloud.
  • FAANG Applications:
    • "Design a Social Graph Traversal" (Meta/LinkedIn): Providing a `FriendIterator` that abstracts away the complexity of a Graph traversal (BFS/DFS) behind `hasNext()` and `next()`.
    • "Design a Database Cursor" (Oracle/MongoDB): Returning a cursor object that fetches rows incrementally from a database without loading the entire multi-GB result into RAM.

☕ Java Implementation

interface Iterator {
    boolean hasNext();
    T next();
}

class BookCollection {
    private String[] books = {"Design Patterns", "Clean Code"};
    
    public Iterator createIterator() {
        return new BookIterator();
    }
    
    private class BookIterator implements Iterator {
        private int position = 0;
        
        public boolean hasNext() { return position < books.length; }
        public String next() { return books[position++]; }
    }
}

4. Mediator

🎯 Interview Cheat Sheet

  • The Core Concept: Restricts direct communications between objects and forces them to collaborate only via a central mediator object. Reduces chaotic dependencies.
  • Mental Model: Think of an Air Traffic Controller. Planes don't talk directly to each other to decide who lands. They all talk to the Tower (Mediator), which orchestrates the runway logic.
  • FAANG Applications:
    • "Design a Chat Room" (Discord/Slack): Users don't hold direct socket connections to every other user. They send messages to the ChatServer (Mediator) which broadcasts them.
    • "Design a Complex UI Form" (Apple): When a "State" dropdown changes, it notifies the `FormMediator` which then disables/enables the "Zip Code" input, preventing spaghetti event listeners.

☕ Java Implementation

interface ChatMediator {
    void sendMessage(String msg, User user);
    void addUser(User user);
}

class ChatRoom implements ChatMediator {
    private List users = new ArrayList<>();
    
    public void addUser(User user) { users.add(user); }
    public void sendMessage(String msg, User sender) {
        for (User u : users) {
            if (u != sender) u.receive(msg);
        }
    }
}

class User {
    private ChatMediator mediator;
    public User(ChatMediator m) { this.mediator = m; }
    public void send(String msg) { mediator.sendMessage(msg, this); }
    public void receive(String msg) { /* Handle msg */ }
}

5. Memento

🎯 Interview Cheat Sheet

  • The Core Concept: Lets you save and restore the previous state of an object without revealing the details of its implementation (encapsulation).
  • Mental Model: Think of a Video Game Save State. The game engine creates a snapshot (Memento) of your health, position, and inventory. The memory card (Caretaker) holds the snapshot but can't tamper with its internal data.
  • FAANG Applications:
    • "Design a Text Editor Undo Feature" (Google Docs): Creating snapshots of the document state. Often paired with the Command pattern for robust Undo/Redo architectures.
    • "Design a Database Transaction Rollback" (Oracle): Saving the state of records before a transaction begins, so they can be seamlessly restored if the transaction fails.

☕ Java Implementation

// Memento (Immutable snapshot)
class EditorState {
    private final String content;
    public EditorState(String content) { this.content = content; }
    public String getContent() { return content; }
}

// Originator
class Editor {
    private String content = "";
    public void setContent(String content) { this.content = content; }
    
    public EditorState createSnapshot() {
        return new EditorState(content);
    }
    public void restore(EditorState state) {
        this.content = state.getContent();
    }
}

// Caretaker
class History {
    private Stack states = new Stack<>();
    public void push(EditorState state) { states.push(state); }
    public EditorState pop() { return states.pop(); }
}

6. Observer

🎯 Interview Cheat Sheet

  • The Core Concept: Defines a subscription mechanism to notify multiple objects about any events that happen to the object they're observing.
  • Mental Model: Think of a YouTube Channel Subscription. You (Observer) subscribe to a Channel (Subject). When the channel uploads a video, you receive a notification automatically. You don't need to constantly refresh the page.
  • FAANG Applications:
    • "Design a Stock Ticker Dashboard" (Bloomberg): Multiple UI widgets (graphs, tables, tickers) subscribe to a single `StockData` feed and update automatically on price changes.
    • "Design a Publisher/Subscriber System" (Kafka/RabbitMQ): The foundational pattern behind event-driven microservices architecture.

☕ Java Implementation

interface Observer { void update(String event); }

class Subject {
    private List observers = new ArrayList<>();
    
    public void subscribe(Observer o) { observers.add(o); }
    public void unsubscribe(Observer o) { observers.remove(o); }
    
    public void notifyObservers(String event) {
        for (Observer o : observers) { o.update(event); }
    }
}

class EmailListener implements Observer {
    public void update(String event) {
        System.out.println("Sending email about: " + event);
    }
}

7. State

🎯 Interview Cheat Sheet

  • The Core Concept: Lets an object alter its behavior when its internal state changes. It appears as if the object changed its class.
  • Mental Model: Think of a Vending Machine. If you press "Dispense" while it's in the `NoCoinState`, it errors out. If you press it in the `CoinInsertedState`, it dispenses. Instead of giant `if/else` blocks, behavior is delegated to state objects.
  • FAANG Applications:
    • "Design a Document Publishing Workflow" (WordPress): A document moves between `Draft`, `Moderation`, and `Published` states, each with vastly different permission behaviors.
    • "Design a Media Player" (Spotify): Handing play/pause clicks differently depending on whether the player is in `PlayingState`, `PausedState`, or `LockedState`.

☕ Java Implementation

interface State { void pressPlay(MediaPlayer context); }

class PausedState implements State {
    public void pressPlay(MediaPlayer context) {
        System.out.println("Resuming playback.");
        context.setState(new PlayingState());
    }
}

class PlayingState implements State {
    public void pressPlay(MediaPlayer context) {
        System.out.println("Pausing playback.");
        context.setState(new PausedState());
    }
}

class MediaPlayer {
    private State state = new PausedState();
    public void setState(State state) { this.state = state; }
    public void clickPlay() { state.pressPlay(this); }
}

8. Strategy

🎯 Interview Cheat Sheet

  • The Core Concept: Defines a family of algorithms, encapsulates each one, and makes them interchangeable at runtime.
  • Mental Model: Think of Google Maps Navigation. You want to go from A to B. You can click "Drive", "Walk", or "Transit". The RouteCalculator (Context) delegates to a specific Algorithm (Strategy) to compute the ETA.
  • FAANG Applications:
    • "Design a Payment Checkout" (Amazon): Selecting between `CreditCardStrategy`, `PayPalStrategy`, or `CryptoStrategy` seamlessly at runtime.
    • "Design a Sorting Utility" (Java Collections): Passing a specific `Comparator` (Strategy) to `Collections.sort()` without rewriting the sorting mechanism itself.

☕ Java Implementation

interface PaymentStrategy { void pay(int amount); }

class CreditCardStrategy implements PaymentStrategy {
    public void pay(int amount) { System.out.println("Paid with CC: " + amount); }
}

class PayPalStrategy implements PaymentStrategy {
    public void pay(int amount) { System.out.println("Paid with PayPal: " + amount); }
}

class ShoppingCart {
    private PaymentStrategy strategy;
    
    // Switch strategy dynamically at runtime
    public void setPaymentStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;
    }
    
    public void checkout(int amount) {
        strategy.pay(amount);
    }
}

9. Template Method

🎯 Interview Cheat Sheet

  • The Core Concept: Defines the skeleton of an algorithm in the superclass but lets subclasses override specific steps of the algorithm without changing its overall structure.
  • Mental Model: Think of Baking a Cake. The recipe (Template) says: 1. Mix ingredients, 2. Bake, 3. Frost. Subclasses like `ChocolateCake` and `VanillaCake` use the exact same process but implement "Mix" and "Frost" differently.
  • FAANG Applications:
    • "Design a Data Miner" (Google): The base class dictates `openFile()`, `extract()`, `parse()`, and `closeFile()`. PDF and CSV subclasses only override the extraction parsing logic.
    • "Design a UI Framework" (Android/React): Lifecycle methods like `onCreate()`, `onStart()`, and `onDestroy()` are abstract steps in a fixed UI template that developers override.

☕ Java Implementation

abstract class DataParser {
    // The Template Method (often declared final)
    public final void parseData() {
        openFile();
        extractData();
        closeFile();
    }
    
    void openFile() { System.out.println("Opening file."); }
    void closeFile() { System.out.println("Closing file."); }
    
    // Step left for subclasses
    abstract void extractData();
}

class CSVParser extends DataParser {
    @Override
    void extractData() { System.out.println("Extracting CSV rows."); }
}

10. Visitor

🎯 Interview Cheat Sheet

  • The Core Concept: Lets you separate algorithms from the objects on which they operate. Avoids polluting domain classes with unrelated logic via "Double Dispatch".
  • Mental Model: Think of an Insurance Agent (Visitor). The agent knocks on the door of a `House`, a `Bank`, and a `Factory`. The building "accepts" the agent, and the agent executes a specific policy review tailored to that specific building type.
  • FAANG Applications:
    • "Design a Compiler/AST Parser" (Apple/LLVM): You have an AST with `AssignmentNode`, `IfNode`, etc. Instead of adding `exportToXML()`, `compileToAssembly()`, and `typeCheck()` methods to every node, you create Visitor classes that traverse the nodes.
    • "Design a Tax Calculator" (Intuit): Applying different tax formulas to `Cigarette`, `Liquor`, and `Necessity` classes without changing their code.

☕ Java Implementation

interface Visitor {
    void visit(House house);
    void visit(Bank bank);
}

interface Element {
    void accept(Visitor visitor);
}

class House implements Element {
    public void accept(Visitor visitor) { visitor.visit(this); }
}

class InsuranceAgent implements Visitor {
    public void visit(House house) {
        System.out.println("Selling medical insurance to residents.");
    }
    public void visit(Bank bank) {
        System.out.println("Selling theft insurance to bank.");
    }
}
